Guide du chef d’établissement

Mise en route, gestion au quotidien et dépannage. Touchez une rubrique pour la lire.

1. Mise en route (une seule fois)

Dans Supabase, ouvrez SQL Editor › New query, collez le contenu du fichier indiqué, puis touchez Run. Respectez cet ordre :

  1. schema.sql : base de données de l’application.
  2. partage-parents.sql : liens de suivi pour les parents.
  3. partage-admin.sql : dossiers élèves et lien unique famille.
  4. acces-admin.sql : liste des administrateurs.
  5. code-enseignant.sql : l’enseignant peut afficher le code famille de ses élèves.
  6. securite-v32.sql : affectation des élèves aux enseignants.
  7. tableau-bord-admin.sql : tableau de bord.
  8. vie-scolaire-admin.sql : enseignants, discipline, fin de période.

Ces scripts peuvent être relancés sans risque. Ensuite : collez la clé publique dans js/supabase.js, renseignez les adresses autorisées (Authentication › URL Configuration : https://classemaster.github.io/ et https://classemaster.github.io/**), puis publiez les fichiers sur GitHub. Le détail est dans supabase/LISEZ-MOI.md.

2. Donner l’accès administrateur à un compte
  1. La personne crée d’abord son compte dans Classe Master (avec son adresse e-mail).
  2. Dans acces-admin.sql, remplacez VOTRE-ADRESSE@EXEMPLE.COM par son adresse, puis lancez le script.
  3. Elle ouvre etab-accueil.html (bouton « Gestion de l’établissement » dans Compte).

Pour retirer l’accès, utilisez la ligne « Retirer l’accès » à la fin du même script. Si la page affiche « Accès réservé », l’adresse n’a pas été ajoutée, ou ne correspond pas exactement.

3. Au quotidien
  • Rubriques (menu en haut de chaque page) : Accueil (indicateurs et alertes), Classes (élèves, codes, cartes QR, effectifs, transferts), Enseignants (demandes, affectations), Matières, Résultats et assiduité (avec filtres classe, matière et enseignant, tableau classe × matière et provenance des données), Vie scolaire (discipline, messages), Fin d’année, Paramètres (code de l’établissement, seuils, journal).
  • Affecter une classe à un enseignant : rubrique « Enseignants » (classe et matière ; les anciens accès par e-mail et classe y restent listés). Sans affectation, l’enseignant ne peut pas afficher le code famille des élèves de cette classe.
  • Lien unique pour une famille : les parents ouvrent un seul lien qui regroupe toutes les matières de leur enfant.
  • Fin d’année : enregistrez ici les décisions de passage et préparez la rentrée.
Consulter sans internet

Sur votre appareil personnel, ouvrez la rubrique « Paramètres » avec internet et cochez « Garder les données sur cet appareil ». Ouvrez ensuite chaque rubrique une fois (et chaque année utile dans « Fin d’année ») : elle sera consultable sans réseau.

Hors ligne, un bandeau indique la date des données et les modifications sont désactivées. Les codes famille, les téléphones des parents et le code des enseignants ne sont pas gardés. Tout est effacé à la déconnexion, ou après 30 jours sans mise à jour. Ne l’activez pas sur un appareil partagé.

4. Avant chaque mise à jour du site
  1. Lancez node outils/tests.js : tous les tests doivent réussir.
  2. Changez VERSION en haut de sw.js (par exemple cm-v54 puis cm-v55) : sinon les téléphones gardent l’ancienne version.
  3. Publiez sur le dépôt GitHub classemaster.github.io. Demandez aux enseignants de fermer puis rouvrir l’application avec internet.
5. Dépannage
  • « Statistiques indisponibles » : relancez tableau-bord-admin.sql.
  • Rubriques Enseignants, Vie scolaire ou Fin d’année « Indisponibles » : lancez vie-scolaire-admin.sql.
  • La page admin affiche « élément absent côté serveur » : un script SQL manque. Reprenez la liste de la rubrique 1.
  • « Action non autorisée » : le compte n’est pas administrateur (rubrique 2), ou la classe n’est pas affectée à l’enseignant.
  • Impossible de se connecter : vérifiez les adresses autorisées dans Authentication › URL Configuration.
  • Bouton Google « pas activé » : renseignez l’identifiant et le secret Google dans Authentication › Providers › Google, ou ignorez ce bouton.
  • Les enseignants ne voient pas la nouvelle version : VERSION de sw.js non changée (rubrique 4).
  • Une donnée semble perdue : demandez à l’enseignant de regarder la corbeille (Compte › Espace et sauvegarde) ou de restaurer sa dernière sauvegarde complète.
6. Données personnelles et sécurité
  • La clé publique de js/supabase.js est faite pour être publique : la protection vient des règles Supabase (RLS) installées par les scripts SQL.
  • Ne partagez jamais la clé « service role » de Supabase ni le mot de passe de votre compte Supabase.
  • Les parents n’ont accès qu’à la lecture, et seulement avec leur code famille. Les incidents de discipline ne leur sont pas visibles.
  • Les noms et notes des élèves sont des données sensibles : n’envoyez pas de captures de la page d’administration par messagerie ouverte.
